# Supabase Üzerinden Gerçek Müşteri Linki — Kurulum ve Test

> **Güncelleme:** Güvenlik için `GUCLENDIRME-REHBERI.md` → bölüm 4 izinleri sıkılaştırır (yalnızca sen yayınlayabilirsin). Bu rehberdeki ilk kurulumdan sonra o adımları uygula.

## Ne değişti?
"Yayına Hazırla"ya basınca:
1. Eskisi gibi bu tarayıcıya yerel yayın yapılır (`view.html?doc=...` çalışmaya devam eder).
2. Supabase ayarlıysa: görseller/video/müzik Supabase Storage'a yüklenir, davetiye `published_invitations` tablosuna yazılır.
3. Ekranda müşteri linki çıkar: `view.html?slug=ayse-mustafa-a7k3p9`
4. Aynı davetiye tekrar yayınlanırsa **aynı link** güncellenir, yeni kayıt açılmaz.

Supabase ayarları boşsa editör birebir eskisi gibi çalışır.

## Dosyalar
| Dosya | Durum |
|---|---|
| `js/supabase-config.js` | **YENİ** — URL ve anon key buraya |
| `js/core/cloud-store.js` | **YENİ** — Supabase'e yazma/okuma |
| `js/editor/publish.js` | 2 fonksiyon eklendi |
| `js/editor/editor-app.js` | Yalnızca "Yayına Hazırla" butonunun işlemi |
| `js/view-app.js` | `?slug=` desteği eklendi, `?doc=` aynen duruyor |
| `index.html`, `view.html` | 2'şer `<script>` satırı |

Dokunulmayanlar: `storage.js`, `blob-store.js`, `renderer.js`, tüm modüller, giriş sahnesi, ZIP paketi.

## ADIM 1 — Anahtarları yaz
`js/supabase-config.js` dosyasını aç:
- `url` → Supabase → Project Settings → API → **Project URL**
- `anonKey` → aynı sayfadaki **anon / publishable** anahtar
- `publicViewUrl` → view.html'in yayında olacağı tam adres (ör. `https://davet.studioseoz.com/view.html`)

⚠️ `service_role` / `secret` anahtarını ASLA yazma. Yazılırsa sistem onu reddeder.

## ADIM 2 — Görseller için Storage bucket'ı aç
Supabase → **SQL Editor** → aşağıdakini yapıştır → **Run**:

```sql
-- Herkese açık medya klasörü
insert into storage.buckets (id, name, public)
values ('davetiye-medya', 'davetiye-medya', true)
on conflict (id) do nothing;

-- Editörün dosya yükleyebilmesi için
create policy "davetiye-medya yukleme"
on storage.objects for insert to anon
with check (bucket_id = 'davetiye-medya');
```

## ADIM 3 — Tabloyu kontrol et
`id` kolonu otomatik numara vermiyorsa yayın "null value in column id" hatası verir. O zaman bunu çalıştır:

```sql
alter table public.published_invitations
alter column id add generated by default as identity;
```

## ADIM 4 — Test
1. Editörü aç, bir davetiyede **Yayına Hazırla**'ya bas.
2. "Yayınlandı. Müşteri bağlantısı: ..." kutusu çıkmalı → linki kopyala.
3. Supabase → Table Editor → `published_invitations` → 1 satır görünmeli.
4. Linki **telefonda** veya **gizli pencerede** aç → davetiye görselleriyle açılmalı.
5. Davetiyede küçük bir değişiklik yap, tekrar **Yayına Hazırla** → link **aynı** kalmalı, tabloda hâlâ **1 satır** olmalı, link yeni hâli göstermeli.
6. `view.html?slug=olmayan-bir-sey` → "Davetiye bulunamadı veya henüz yayınlanmadı."
7. Eski `view.html?doc=...` linki aynı tarayıcıda hâlâ açılmalı.

## Bilmen gerekenler
- **Güvenlik (önemli):** Şu anki `anon UPDATE` politikası, anon key'i bilen herkesin (anahtar view.html ile herkese açıktır) tablodaki davetiyeleri değiştirebilmesi demek. Test için sorun değil; gerçek müşterilere geçmeden önce editöre Supabase girişi ekleyip INSERT/UPDATE'i yalnızca giriş yapan kullanıcıya açmayı öneriyorum.
- **Slug bu tarayıcıda saklanır.** Başka bilgisayardan veya JSON içe aktararak yayınlarsan davetiye yeni bir link alır (eski link eski hâlini gösterir).
- **Dosya boyutu:** Supabase ücretsiz planında tek dosya sınırı 50 MB. Giriş videosu bundan büyükse yükleme hata verir.
- **Hosting:** `view.html`, `js/` ve `css/` klasörleri bir kez hostinge yüklenir (`supabase-config.js` dahil). Sonrasında her yeni davetiye için ZIP yüklemeye gerek kalmaz; sadece link verilir.
- "Yayın Paketi İndir (.zip)" eskisi gibi çalışır, Supabase'den bağımsızdır.
